# Architecture Decision Records

Short records of decisions that shape the code. Each one keeps the context
and the alternatives, so a later reader can tell whether the reasons still
hold.

## Writing a new ADR

Copy the structure of an existing one: **Status, Context, Decision,
Alternatives considered, Consequences**. Number it sequentially. When a
decision changes, update the ADR it belongs to and keep the rejected option
under "Alternatives considered", so one record describes the current design.
